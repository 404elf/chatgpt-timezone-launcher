# v1.1.1 — 修复启动时静默退出并增加发布验证

下载附件 `ChatGPT-TimeZone-Launcher-v1.1.1-win-x64.exe`，无需安装 .NET。适用于 Windows 10/11 x64。旧版附件保留，新版不要求删除用户配置。

## 已确认原因

当已有 settings.json 损坏或配置版本无效时，ConfigStore 能返回安全默认值，但 MainForm 构造函数紧接着在窗口句柄创建前调用 BeginInvoke 显示警告，触发 InvalidOperationException。Program 原来只处理消息循环内的 ThreadException，未捕获 Application.Run(new MainForm()) 中的构造异常，因而可能在主界面出现前退出。

旧测试只测配置读取，没有构造窗口。新增回归测试在旧逻辑下得到 20/21，通过项包括原有全部 20 项；失败信息为“在创建窗口句柄之前，不能在控件上调用 Invoke 或 BeginInvoke”。修复后 21/21 通过。

## 修复

- 配置恢复提示直接显示在主窗口“状态与诊断”内，不提前调用 BeginInvoke；损坏原文件保留。
- 启动初始化、窗口构造及消息循环异常写入诊断日志，并显示包含日志路径的错误对话框。
- 日志位于 `%LocalAppData%\ChatGPTTimezoneLauncher\logs`；不可写时尝试 `%TEMP%\ChatGPTTimezoneLauncher\logs`。不上传日志。
- 项目默认发布为自包含 x64 单文件，避免直接使用 dotnet publish 时意外生成依赖外部运行时的交付包。
- 构建脚本发布后执行最终 EXE 启动检查；顺带修复 SkipTests 会读取上一个命令退出码的问题。

## 验证与边界

- .NET SDK 8.0.425；21/21 回归测试通过。
- 最终 EXE 独立复制到带中文和空格的新目录，不携带任何旁边的 DLL；首次配置和损坏配置均成功创建窗口、运行消息循环并正常退出。
- 检查使用独立配置及全新解压目录，DOTNET_ROOT 指向不存在目录；未启动、关闭或修改真实 ChatGPT，未改动用户实际配置。
- 测试机已有 .NET，以上不等同于从未安装 .NET 的干净 Windows 虚拟机测试；交付包按自包含方式构建。
